## 今日完成

### 1. 明确当前研究边界

- 当前阶段是基础设施阶段，不是训练阶段。
- 当前示例域仍是有限的命题逻辑，用于验证搜索、状态管理和 Lean 校验链路。

- 完整 proof state 是搜索节点；多个未完成目标不会被错误地拆成彼此独立的任务。
- 状态句柄只是运行时优化，不是证明证书。完整 tactic trace 仍被保留，用于状态身份、恢复和最终验证。

### 2. 完成持久化 Lean Driver 的状态句柄路径

Driver 现在支持：

- `createState`：建立根 proof state；
- `applyState`：恢复指定父状态，执行一个 action，并保存独立子状态；
- `releaseState`：释放不再需要的进程内状态；
- `probe`：保留完整 trace replay 路径；
- `ping`：检查 Driver 与协议版本。

Lean 端保存的不只是 goal 文本，而是：

- `Core.State`；
- `Meta.State`；
- `Term.State`；
- `Tactic.State`；
- 对应的 Core、Meta、Term 和 Tactic reader contexts。

这样可以在不同 JSONL 请求之间恢复完整分支，同时避免子分支修改父状态。

### 3. 修复状态恢复中的 metavariable 冲突

最初只调用 Lean 默认的 `Tactic.SavedState.restore`。该恢复只覆盖可回溯字段，
跨 JSONL 请求时会因为新的命令重复使用 name-generator counter，造成
metavariable ID 冲突和错误的多目标状态。

修复方式是完整恢复 Lean monad stack 中的可变状态，并在 action 执行期间恢复
保存的 reader contexts。修复后，`constructor` 可以稳定返回两个真实未完成目标，
父状态也可以安全地产生多个 sibling branches。

### 4. 修复“错误 tactic 被当成成功”的正确性漏洞

回归 demo 曾发现：在证明 `P → Q → P ∧ Q` 时，搜索错误地接受了
`exact h0.1`，但最终独立 Lean 验证会拒绝该证明。

原因是 Lean tactic elaborator 会在部分错误场景中恢复，并插入 synthetic
`sorry`；随后包装状态恢复又清除了错误消息，使 Driver 将该分支误判为成功。

现在执行 action 时同时使用：

- `Tactic.withoutRecover`；
- `Term.withoutErrToSorry`。

因此 tactic elaboration error 会直接使转换失败，不会产生成功的 child state。
新增回归测试确保对原子命题假设使用 `.1` 会被拒绝，而且失败分支不会破坏父状态。

### 5. 完成 Python 侧状态句柄接入

- `LeanProofState` 增加进程内 `driver_state_id`。
- 初始状态通过 `create_state` 创建。
- 默认转换通过 `apply_state` 单步执行，不再为每个候选重放完整前缀。
- state ID 不进入 canonical payload，因为它不是稳定的语义身份。
- Driver 重启导致 state ID 丢失时，自动降级为完整 trace replay，保证正确性。
- one-shot Lean replay backend 仍保留，可用于对照和故障排查。

### 6. 增加状态生命周期管理

- 搜索记录本次运行创建的所有临时 Lean states。
- 搜索正常结束、预算耗尽或异常退出时，都会进行 best-effort cleanup。
- 多个 state IDs 会在一个 Driver 请求中批量释放，避免长搜索中状态表无限增长。
- 修复了 Driver 关闭后 stdin/stdout/stderr 文件对象未显式关闭产生的
  `ResourceWarning`。

```text
best_first_search
  → LeanEnvironment
    → LeanBridge
      → persistent JSONL Driver
        → restore parent state/context
        → strictly elaborate one tactic
        → save child state
        → return every open goal

solved trace
  → fresh Lean process
    → replay without sorry
      → kernel acceptance
```
